# Arbiter AI progress from the initial run

Arbiter's latest public-data checkpoint saved **20,002 decisions**, retained
**17,304 of 17,305 attack-labelled records**, and removed **64.67% of the
unannotated warnings raised by L1**. The newest source update separates short
AI decisions from longer reports using a CPU worker and reusable templates.

Qwen3.5:4b is the first reviewer, or **L1**. Gemma4:12b is the second reviewer,
or **L2**, receiving eligible escalations from L1. **Suppressed** means quieted;
**escalated** means kept visible for investigation. The public source is
[AIT Alert Data Set v1](https://zenodo.org/records/8263181). **Unannotated** means
no publisher attack label; it does not independently certify benign activity.

### Correct attack flagging by attack type

| Attack type | Correctly flagged / attack-labelled records | Correctly flagged percentage |
|---|---:|---:|
| Web directory scanning | 17,293 / 17,293 | **100%** |
| Online password guessing | 2 / 2 | **100%** |
| Attacker-associated account/session activity | 2 / 3 | **66.67%** |
| Privileged attack-phase commands | 7 / 7 | **100%** |
| **Full pipeline total** | **17,304 / 17,305** | **99.994%** |

Correct attack flagging, also called attack recall, is
`17,304 correctly flagged attack-labelled records / 17,305 attack-labelled records × 100`.
The one missed attack represents **0.0058%** of attack-labelled records. The
initial published run had no attack-labelled records, so its attack-flagging
percentage is **not measured**. The small attack-type counts are shown alongside
their percentages.

Most attack records were repeated web scans. Safety rules retained 17,300 attack
records; five reached the models, and Gemma retained four. The 99.994% figure
describes the whole pipeline. The next evaluation will expand the small
account/session and password-attack samples. The final label agreement combines
17,304 retained attack records and 2,426 quieted unannotated records; remaining
outcomes were one missed attack and 271 retained unannotated warnings.

## What the newest update changes

These changes are implemented and software-tested **after** the measured
checkpoint. They are available in the source; the installed dashboard and
benchmark remain stopped.

| Area | What happened in the measured run | What is available in the new code | Status |
|---|---|---|---|
| Gemma's answer | Decision and long explanation generated together. | A short decision, reason, competing explanations and evidence IDs. | Implemented; real-model timing retest next. |
| Report writing | Most answer time went into generating text. | A separate **CPU report worker** formats saved evidence without another AI call. | Implemented and tested. |
| Templates | Each model review generated its narrative anew. | **Six templates:** account/session, web, network, software/update, process and generic activity. | Implemented and tested. |
| Context | The full explanation was part of the decision call. | Actual input context, short reason, confidence and decision saved for later reporting. | Implemented for both brains. |
| Learned rules | Zero learned-pattern hits. | Each learned rule also carries its template, original model and reviewed-event reference. | Template linkage implemented; matching scope unchanged. |
| Evidence errors | Eleven replies failed exact-evidence checks. | Gemma selects IDs from supplied facts instead of retyping fields and values. | Implemented and software-tested. |
| Report delays or errors | Long narratives occupied the model. | Decisions complete independently; pending reports recover after restart. | Slow/failed-worker and recovery tests passed. |
| Human corrections | Later overrides must remain authoritative. | An older report cannot overwrite a newer decision; reports rebuild after rejection. | Concurrency and override tests passed. |
| Dashboard | The operator depended on completed analysis. | Partial facts during review, followed by the final saved report and worker status. | Updated in source/build; installed app remains stopped. |

Templates format evidence; they do not grant suppression authority. Confidence
requirements, suppression checks and final guardrails remain enforced. A later
learned match names the original reviewed event and identifies the current
decision as a pre-filter match, rather than claiming a fresh model review.

## Suppression and escalation timing

These are valid completed Gemma reviews **before the compact-decision update**.
Answer generation includes both the decision and explanation. Queue waiting is
excluded from the timings below.

| Final outcome | Valid reviews | Average answer generation | Average full L2 model review |
|---|---:|---:|---:|
| Suppress | 497 | **26.81s** | **34.84s** |
| Escalate or keep visible | 250 | **28.30s** | **32.67s** |

Suppression requires a checking call. Most direct escalations skip it; 24 final
escalations began as proposed suppressions and were overridden by the checks.
Both outcomes spend substantial model time generating their combined answers,
which is why longer report writing now has a separate CPU worker.
